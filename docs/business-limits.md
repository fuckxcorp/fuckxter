# 0.9.5 业务限流与密码校验

## 限额

| 操作                                                         | 每分钟 | 每 24 小时 |
| ------------------------------------------------------------ | -----: | ---------: |
| 发帖、回帖、引用转发、直接转发、回复转发，合计               |     30 |        300 |
| 点赞、收藏、关注、拉黑、编辑、删除、撤回、标记私信已读，合计 |    120 |       3000 |
| 发送私信，所有收件人合计                                     |     60 |       2000 |
| 同一发送者给同一收件人发私信                                 |     20 |        500 |

这些业务写操作还共用来源 IP 每分钟 300 次的限制。浏览计数单独限流：登录账号每分钟 120 次，访客按来源 IP 每分钟 120 次，所有账号与访客合计每来源 IP 每分钟 600 次。单条和批量计数共用额度；批量最多 20 个帖子 ID 的限制不变。

窗口从第一次计数开始计算，不是自然日。计数覆盖操作尝试，包括被业务权限拒绝或被限流拒绝的请求，防止不断重试逃避配额。业务限流使用 D1 原子批量 UPSERT，多个维度一次数据库往返计数；账号与收件人绑定固定 credential_id，改名不会重置。IP 来自 Cloudflare 的 CF-Connecting-IP，不接受请求体中的身份或来源字段。

限流发生在业务写入之前，返回 HTTP 429、RATE_LIMITED 和 Retry-After，后者为重新允许请求至少需要等待的秒数。浏览计数的阅读权限、去重和只读接口不受此写操作限流改变。阈值集中在 worker/shared/rate-limit.ts。

## 密码与邮箱

注册和改密码共用后端校验：必须是字符串，长度为 8–128 个 Unicode 字符。直接调用 API 也不能绕过；超长密码不进入新密码哈希计算。已有旧密码账号仍能登录，未强制注销或重设密码。

邮箱归属验证按本次用户决定另行接入发信服务。此版本没有增加邮件发送、邮箱验证状态或切换现有自动注册行为；未验证邮箱仍不能用于管理员授权。

## 验证

- scripts/verify-security.cjs：23 组安全与数据回归；新增覆盖注册及改密码边界、旧账号兼容、跨接口额度、私信收件人、改名及换 IP、每日额度与窗口恢复、并发拒绝。
- 独立本地 Worker/D1/KV/R2/队列环境：真实 HTTP 验证弱密码拒绝、40 个并发发帖只写入 30 条、HTTP 429 与 Retry-After、单条与批量计数共用额度、账号及访客去重和只读访问。
- 邮箱发信、线上 WAF、生产负载及上线后阈值效果不在本轮验证范围。

本次不新增数据库迁移，但依赖 0.9.4 的 0023_security_and_storage.sql 中的 rate_limits 表；生产数据库需已应用此迁移。GitHub 推送保持不自动构建或部署。

## 另一个既有问题

隔离测试发现，0013_direct_messages.sql 的私信外键没有 ON UPDATE CASCADE：已有私信的账号修改其 users.id 时可能被外键拒绝。该问题没有在本次限流修复中修改；限流的固定身份设计不依赖用户名，可在后续修复改名关系时继续有效。
