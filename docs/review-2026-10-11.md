## 安全

### S1 — 重设双重验证无需验证原凭据（P1）

位置：[accounts.ts:407](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/accounts/accounts.ts:407)、[index.ts:638](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/index.ts:638)。`/me/2fa/setup` 只要求已有会话；`beginTwoFactor()` 写入新密钥时直接把 `two_factor_enabled` 设置为 0，既不验证密码，也不验证原动态码。恢复码的重新生成也只依赖当前会话。

本地对一个已经开启双重验证的模拟账号调用设置函数，确认产生了关闭原验证的 SQL。前提是攻击者已经取得有效会话，或操作未锁定的登录设备；这不是无需登录的漏洞。它会让会话劫持者进一步替换验证因素，正常用户重新设置后中途退出也会失去原验证保护。

可选方案：重设前验证原因素或恢复凭据；新密钥保存在待确认字段中，确认成功后再替换旧密钥。依据：[OWASP 更换 MFA 因素](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html#changing-mfa-factors)。

### S2 — 改密码后旧会话仍然有效（P1）

位置：[accounts.ts:376](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/accounts/accounts.ts:376)、[security.ts:6](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/accounts/security.ts:6)。修改密码只更新密码哈希，不删除或轮换 `sessions`；会话有效期为 30 天。后续会话校验只检查令牌及过期时间。

本地调用确认改密码仅执行用户表更新，没有撤销会话。用户用改密码处理账号被盗时，已取得的旧会话仍可继续使用到过期或被单独注销。

可选方案：密码变更后撤销其他会话，并轮换当前会话；如需保持设备登录，应明确提示并提供全部退出能力。依据：[OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

### S3 — 认证尝试没有应用层限流（P1，部署条件需核实）

位置：[accounts.ts:106](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/accounts/accounts.ts:106)、[index.ts:277](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/index.ts:277)。登录、动态码、恢复码路径没有账号/IP 尝试计数或渐进退避，也没有注册及上传的应用层频率限制。本地对模拟账号连续 20 次错误密码均返回 401，没有 429 或锁定。

如果线上也没有 WAF 限流，密码撞库、动态码猜测及注册滥用可以持续执行。当前证据只确认应用层缺失，不能断言 Cloudflare 侧完全没有防护。

可选方案：账号与来源组合限流、短时渐进退避，配合边缘层规则，避免用永久锁号造成反向拒绝服务。依据：[OWASP 登录节流](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#login-throttling)。

### S4 — 自定义存储存在未经约束的服务端外连入口（P2）

位置：[s3.ts:67](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/accounts/s3.ts:67)、[s3.ts:253](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/accounts/s3.ts:253)、[storage.ts:111](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/posts/storage.ts:111)。Endpoint 校验只检查 `http(s)://` 前缀，没有限制内网、回环地址、端口或 URL 凭据。测试连接和代理上传的 `fetch()` 默认跟随重定向；签名读取路径虽使用 `redirect: "manual"`，最初地址仍由用户控制。

拦截网络的本地调用确认 `http://127.0.0.1:8000` 能进入 PUT、DELETE 请求目标，且测试连接保留默认重定向行为。没有真正访问该地址，也没有证明生产 Cloudflare Worker 能访问内网或云元数据。因此结论是确认存在 SSRF 入口，实际可达范围仍需部署环境验证。

可选方案：允许用户自定义公开 S3 服务，但严格解析 URL，限制协议、端口与私网目标，处理 DNS 和重定向后的地址校验，并设置超时。依据：[OWASP SSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

### S5 — 私密帖的浏览计数接口没有复用阅读权限（P2）

位置：[posts.ts:371](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/posts/posts.ts:371)、[index.ts:859](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/index.ts:859)。普通读取使用 `viewerFilter()` 检查公开、互关、私密及拉黑关系；`recordPostView()` 只检查帖子 ID 存在且未删除，匿名调用也可以写入浏览记录并返回浏览量。

本地模拟路径确认，无阅读权限的调用仍进入计数写入并返回数量。影响是泄露帖子的存在/计数信息及修改计数，不是直接读取私密正文。帖子 ID 格式为时间与递增序号，不能把 ID 难猜作为权限控制。

可选方案：计数之前执行与读取一致的权限检查，统一不可见帖子的响应。

### S6 — S3 直传完成确认绕过上传大小与文件头校验（P2）

位置：[media.ts:265](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/posts/media.ts:265)、[media.ts:318](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/worker/posts/media.ts:318)。代理上传有 30 MiB 上限和图片头检测；`finalizeMediaUpload()` 只检查 HEAD 返回的大小是正整数，并接受客户端声明的图片类型。

本地拦截 HEAD 返回 100 MiB、`text/plain`，以 `image/png` 申报仍被登记成功。即使当前界面默认使用代理上传，直传 API 仍对登录用户开放。问题会造成类型与大小规则不一致，并增加大文件的传输和资源消耗；媒体响应已有 `nosniff` 与 sandbox 策略，本次没有据此确认脚本执行漏洞。

可选方案：完成确认时执行相同大小限制、实际类型检测，并把对象与已发出的上传票据绑定。

### U2 — 草稿静默截断，且跨账号共用（P1，兼有隐私影响）

位置：[feed.ts:223](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/src/lib/feed/feed.ts:223)、[auth.ts:158](/Users/middlex/Documents/DocumentsGD/仓库/項目/玩具项目/fuckxter/src/lib/accounts/auth.ts:158)。草稿存放在 `fk-post-draft` Cookie，编码后超过 3,500 字符就从尾部裁掉。保存和恢复均不绑定账号，注销也不清理该 Cookie。

浏览器实际输入 1,000 个“中”，刷新后只恢复 388 个，用户没有得到截断提示。同一浏览器换账号或注销后，未发布草稿仍可能显示。Cookie 的 `Path=/` 还会让同源页面请求携带草稿内容；HTTPS 的 Secure 属性不解决截断或账号隔离。

可选方案：改用按账号隔离的本地草稿存储，完整保留允许的字符数，并明确处理注销、切换账号和过期。

### U3 — Tab 请求较慢时，卡片先消失并被禁止点击（P2）

### U6 — 普通帖子正文没有键盘可用的详情入口（P2）
